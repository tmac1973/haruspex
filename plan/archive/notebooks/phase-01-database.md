# Phase 01 — Database, file store and Rust commands

**Depends on:** nothing · **Enables:** every later phase (all notebook data goes
through these commands)

## Goal
Notebooks exist in SQLite, with all their data: notebooks, cards, table rows,
tags, pins, card revisions, trash, keyword search, and a durable store for
attachment and image files. Typed Tauri commands expose it all. The UI comes
in phase 02. This phase can be tested on its own with `cargo test`, and the
TypeScript bindings are generated.

## Steps
1. **Schema.** Add these tables to the `migrate()` batch with `IF NOT EXISTS`:
   - `notebooks(id TEXT PK, title TEXT NOT NULL, pinned INTEGER NOT NULL
     DEFAULT 0, created_at INTEGER, updated_at INTEGER, deleted_at INTEGER NULL,
     links_checked_at INTEGER NULL)`.
     - IDs are short random base32 strings: 8 characters for notebooks, 6 for
       cards and rows.
   - `notebook_tags(notebook_id TEXT, tag TEXT, PRIMARY KEY(notebook_id, tag))`,
     with `ON DELETE CASCADE`.
   - `notebook_cards(id TEXT PK, notebook_id TEXT NOT NULL REFERENCES
     notebooks(id) ON DELETE CASCADE, position REAL NOT NULL, kind TEXT NOT NULL
     CHECK(kind IN ('text','table','checklist','python','attachment','image')),
     title TEXT NOT NULL DEFAULT '', body TEXT NOT NULL DEFAULT '', meta TEXT NOT
     NULL DEFAULT '{}', version INTEGER NOT NULL DEFAULT 1, source TEXT NOT NULL
     DEFAULT '{"kind":"user"}', created_at, updated_at, deleted_at NULL)`.
     - `body` holds the markdown for text cards and the code for Python cards.
     - `meta` holds JSON:
       - table: the column list `[{id,name,type}]`
       - Python: the last output, `ran_at`, and the version of each table it read
       - attachment and image: `{hash, name, mime, size}`
     - Column `type` is one of `text|number|currency|url|date|checkbox|status`.
   - `notebook_rows(id TEXT PK, card_id TEXT NOT NULL REFERENCES
     notebook_cards(id) ON DELETE CASCADE, position REAL NOT NULL, cells TEXT NOT
     NULL)`.
     - `cells` is JSON keyed by column ID.
     - A checklist row's cells are `{"text":…, "done":bool}`.
   - `notebook_revisions(id INTEGER PK, card_id TEXT NOT NULL, created_at
     INTEGER, source TEXT NOT NULL, snapshot TEXT NOT NULL)`.
     - `snapshot` is JSON of the card row plus its rows.
   - `notebook_link_status(notebook_id TEXT, url TEXT, ok INTEGER, status TEXT,
     checked_at INTEGER, PRIMARY KEY(notebook_id, url))`. Phase 15 fills it; it
     is created here so all notebook schema lives in one batch.
   - `notebooks_fts` (FTS5, its own copy like `messages_fts`): columns
     `text, notebook_id UNINDEXED, card_id UNINDEXED, row_id UNINDEXED`.
     - Keep it current from the Rust write paths, not triggers, because the
       text is derived: a card's title and body, each row's cell values joined
       with spaces, the attachment file name, and the notebook title as a row
       with an empty `card_id`.
   - `notebook_embeddings(card_id TEXT, chunk INTEGER, notebook_id TEXT,
     embedding BLOB, embedding_model TEXT, content_hash TEXT, PRIMARY
     KEY(card_id, chunk))`, with an index on `embedding_model`. Phase 09
     fills it. Card and notebook purges delete their rows.
   - Add a `notebook_id TEXT NULL` column to `conversations` through the ALTER
     list (:921-1010). Phase 07 uses it. It is added here so every migration
     is in phase 01.
2. **Source.** The `source` JSON is
   `{"kind":"user"|"chat"|"notebook_chat"|"shell"|"code"|"job"|"python"|"import",
   "ref"?:string, "label"?:string}`.
   - `ref` is the conversation, Code session or job ID, used for the link back.
   - `label` is its title at the time of the change.
3. **Commands.** All are domain-first, async, and run on `on_pool`.
   - **Notebooks:**
     - `notebook_list(include_deleted)` returns summaries: id, title, pinned,
       tags, updated_at, card count.
     - `notebook_get(id)` returns the notebook and its cards. Table and
       checklist cards include only their first 200 rows plus `row_count`.
     - `notebook_create(title, tags, source)`, `notebook_update(id, title?,
       pinned?, tags?)`.
     - `notebook_delete(id)` soft-deletes: it sets `deleted_at`.
     - `notebook_restore(id)`, `notebook_purge(id)`.
   - **Cards:**
     - `notebook_card_add(notebook_id, after_card_id?, kind, title, body, meta,
       rows?, source)`.
     - `notebook_card_update(card_id, expected_version, title?, body?, meta?,
       source)` returns the new card. On a version mismatch it returns
       `Err("conflict")` with the current card.
     - `notebook_card_move(card_id, after_card_id?)` sets fractional `position`
       and renumbers when the gap falls below 1e-6.
     - `notebook_card_delete`, `notebook_card_restore`, `notebook_card_purge`.
   - **Rows:**
     - `notebook_rows_get(card_id, offset, limit)`.
     - `notebook_rows_apply(card_id, expected_version, ops, source)`, where
       `ops` is a list of
       `{op:"add",after?,cells}|{op:"update",row_id,cells}|{op:"delete",row_id}|{op:"move",row_id,after?}`.
       It runs in one transaction, bumps the card's `version`, and caps a table
       at 5,000 rows.
     - `notebook_columns_set(card_id, expected_version, columns, source)` keeps
       cells for column IDs that survive and drops the others.
   - **Revisions:**
     - `notebook_card_history(card_id)` returns id, created_at and source.
     - `notebook_card_revision(id)` returns the snapshot.
     - `notebook_card_rollback(card_id, revision_id, source)`.
   - **Search:** `notebook_search_keyword(query, limit)`. It uses `fts_query()`
     from `camera_events.rs:140` and returns notebook_id, card_id, row_id and a
     `snippet()` excerpt, sorted by bm25.
   - **Trash:** `notebook_trash_list()` returns deleted notebooks, plus deleted
     cards in live notebooks.
   - **Files:**
     - `notebook_file_store(bytes)` takes a raw IPC body with `x-name` and
       `x-mime` headers, like `document_write.rs`, and returns
       `{hash,name,mime,size}`.
     - `notebook_file_store_path(path)` copies a file the user picked or
       dropped and returns the same shape.
     - `notebook_file_path(hash)` returns the absolute path for export and
       "Open with".
   - Every mutating command bumps `notebooks.updated_at`.
4. **Revision recording** happens inside every card and row mutation, in the
   same transaction:
   - Before applying a change, if the newest revision for the card has the same
     `source.kind` and `source.ref` and is under 2 minutes old, replace its
     snapshot timestamp only. The snapshot holds the state before the first
     change in the group.
   - Otherwise insert a new snapshot of the current state.
   - Then delete all but the newest 50 revisions for that card.
   - Rollback snapshots the current state first, so a rollback can itself be
     undone.
5. **Trash purge:** `Database::purge_notebook_trash(now)` hard-deletes
   notebooks and cards whose `deleted_at` is over 30 days old. Run it from the
   existing startup maintenance path, next to the other sweeps in `lib.rs`.
   Purging only deletes rows. Files are removed solely by the stray sweep in
   step 6, so a hash still held by a revision snapshot is never lost.
6. **File store:**
   - Files go in `<app_data>/notebook_files/<sha256>`, using `blob_cache`
     helpers and `is_valid_hash`. They are never evicted while a card that is
     live or in the trash references them.
   - `remove_strays` runs at startup, after the trash purge, against the set
     of hashes referenced by `notebook_cards.meta` (live or in Trash) **or** by
     any `notebook_revisions.snapshot`. `Database::notebook_referenced_hashes()`
     collects both.
   - Size cap: 200 MB per file.
   - The URI scheme serves `haruspex-notebook-file://<hash>` with the stored
     MIME type, following `image_cache/protocol.rs`.
7. Run `./scripts/export-ipc-types.sh`, add the mocks, and write
   `src/lib/notebooks/api.ts`.

## Test plan
Rust unit tests on `open_in_memory()`:
- **CRUD and ordering:** create, add three cards, move the last to the first
  position, and positions reorder. 10,000 moves trigger renumbering.
- **Conflict:** `notebook_card_update` with a stale `expected_version` returns
  conflict and leaves the card unchanged.
- **Rows:** add, update, delete and move in one call is atomic. A bad `row_id`
  rolls back the whole batch. The 5,001st row is refused.
- **Revisions:** two edits by the same source within 2 minutes make one
  revision, and a different source makes two. More than 50 revisions prune to
  50. Rollback restores the body and rows and records a new revision.
- **Search:** a word in a table cell finds that row's card. Deleting the card
  removes its hits. Prefix search works.
- **Trash:** a soft-deleted notebook is hidden from `notebook_list(false)`. A
  purge after 30 days removes it with cascades.
- **Files:** store, dedupe the same bytes, sweep strays, keep a hash
  referenced only by a revision, and refuse an invalid hash.
