# Phase 01 — Instance identity and session times

**Depends on:** nothing · **Enables:** 02 (probe reads it), 04 (mDNS TXT
carries it), 07 (peers keyed by it)

## Goal

Give every Haruspex install a stable random id and a display name, and have
`GET /api/v1/health` answer them. Also add `updatedAt` to each
`sessions.list` row, which has no time today, so a peer's last-known list can
show times and sort like the local one. Peers are keyed by this id, so one found by
mDNS and the same one added by a tailnet name are one computer, and an
instance can recognise and skip itself. Nothing user-visible changes.

## Files touched

- `src-tauri/src/owner/identity.rs` — new: `InstanceIdentity { id, name }`,
  loaded or created at startup.
- `src-tauri/src/owner/mod.rs` — `pub mod identity;`, manage the identity in
  Tauri state.
- `src-tauri/src/owner/server.rs` — `health` answers
  `{ ok, version, instanceId, name }`; `AppState` carries the identity.
- `src-tauri/src/lib.rs` — load the identity in `setup` before the owner API
  starts; register `instance_identity` command.
- `src-tauri/src/owner/commands.rs` — `instance_identity` command (returns the
  struct) for the frontend.
- `src/lib/engine/types.ts` — `SessionListItem.updatedAt?: number | null`.
- `src/lib/engine/dispatch.ts` — `listSessions` fills it from the saved
  session's `updated_at` (null for one never saved).
- `src/lib/ipc/gen/InstanceIdentity.ts` — generated by
  `./scripts/export-ipc-types.sh`.

## Steps

1. `identity.rs`: the id is a UUID v4 string kept in
   `<app_data_dir>/instance-id` (plain text, one line). Not in the settings
   blob, so copying settings to another computer never clones it. Read it if
   present and a valid UUID; otherwise write a new one (write to
   `instance-id.tmp`, then rename). A read or write failure logs a warning and
   uses an in-memory id for this run.
2. The name is `owner::trust::system_hostname()` (already used for the
   certificate's names), cut at the first `.`, falling back to `"Haruspex"`
   when it returns `None` or an empty string.
3. `#[derive(Serialize, ts_rs::TS)] #[serde(rename_all = "camelCase")]
   #[ts(export)] pub struct InstanceIdentity { pub id: String, pub name:
   String }`.
4. `health` adds `instanceId` and `name`. It stays open (no token): a probe
   must read it before trusting anything. The id is not a secret; it only
   identifies an install.
5. `instance_identity` Tauri command, async, returns the managed identity.
6. `listSessions` in `dispatch.ts`: add `updatedAt` from
   `code_sessions.updated_at` as the code store already loads it. The field
   is optional in the type, so a client reading a peer on an older version
   falls back to list order.
7. Run `./scripts/export-ipc-types.sh`.

## Test plan

- Unit (`identity.rs`): a fresh dir creates a file and returns a UUID; a
  second load returns the same id; a garbage file is replaced; an unwritable
  dir yields an id and no panic.
- `dispatch` test: `sessions.list` rows carry `updatedAt`.
- `server.rs` test: extend `health_is_open_and_the_rest_needs_a_token` to
  check `instanceId` and `name` are present and `instanceId` matches the
  harness's identity.
