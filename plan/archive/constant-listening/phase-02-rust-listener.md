# Phase 02 — Rust listener: streaming capture, earshot segmentation, transcription

**Depends on:** 01 (whisper-server with `--vad`; `WhisperServer::transcribe` already exists in
`whisper.rs`) · **Enables:**
03 (the frontend consumes the `voice://listen` events and commands added here).

## Goal
A backend that listens continuously. `voice_listen_start` opens the mic. Speech is split
into phrases with earshot, and each phrase is transcribed by the running whisper-server,
one at a time and in order. Each result goes out as a `voice://listen` event.

Listening pauses while read-aloud (TTS) plays or while the webview says it's holding.
After 5 minutes without speech it stops itself. Push-to-talk and the listener share the
mic, and only one can hold it.

No UI uses it yet, so this phase can be tested only with Rust tests and the devtools
console.

## Steps
1. **Mic lock.**
   - `MicLock(Mutex<Option<MicUser>>)`, where `enum MicUser { PushToTalk, Listening }`.
   - `MicLock::try_take(user) -> Result<MicGuard, String>` fails when another user holds the
     lock. The message names the holder: `"The microphone is in use by constant listening"`
     or `"The microphone is in use by push-to-talk"`.
   - `MicGuard` resets it to `None` on `Drop`.
   - `AudioRecorder::start_recording` takes the guard and keeps it in a new
     `guard: Mutex<Option<MicGuard>>`. `stop_recording` drops it.
   - The `start_recording` command gains `mic: tauri::State<'_, MicLock>`.
2. **Refactor `audio.rs`.**
   - Move the device lookup, `safe_cpal` config, the `build_stream!` macro (downmix to mono
     f32) and `play()` into `open_input_stream`.
   - `on_error` is called from cpal's error callback.
   - `AudioRecorder` passes a closure that pushes into its `samples` buffer. Its behaviour
     doesn't change, and the existing tests keep passing.
3. **Resampler.**
   - `StreamResampler { ratio: f64, pos: f64, last: f32 }`.
   - `push(&mut self, input: &[f32], out: &mut Vec<f32>)` interpolates linearly across the
     chunk boundary, using `last`.
   - When the native rate is already 16 000, it passes samples straight through.
4. **Segmenter.** All the constants are in 16 ms frames (256 samples at 16 kHz):
   - `VOICE_THRESHOLD = 0.5`.
   - `START_FRAMES = 3`: 48 ms of voice opens a phrase.
   - `PREROLL_FRAMES = 20`: 320 ms of audio from before the opening frame is kept.
   - `END_FRAMES = 50`: 800 ms of non-voice closes a phrase.
   - `MIN_SPEECH_FRAMES = 19`: a phrase with less than about 300 ms of voiced frames is
     dropped.
   - `MAX_PHRASE_FRAMES = 1875`: 30 s; at that length the phrase is cut and a new one
     opens straight away.
   - `Segmenter::push(frame: &[f32; 256], score: f32) -> Option<Vec<f32>>` returns a
     finished phrase, including the pre-roll and up to `END_FRAMES` of trailing silence
     trimmed to 200 ms.
   - `reset()` clears everything. It's used on hold and stop.
5. **Events.** In `voice_listen/mod.rs`:
   `#[derive(Serialize, TS)] #[serde(tag = "type")] #[ts(export)] enum ListenEvent`.
   Every variant carries `session: u64`:
   - `Started`
   - `Paused { paused: bool }`
   - `PhraseQueued { seq: u32 }`
   - `Phrase { seq: u32, text: String }`. Text that is empty after `trim` is still sent, so
     the frontend can clear its pending count.
   - `Error { message: String }`
   - `Stopped { reason: StopReason }`, where `StopReason` is `User | Idle | Device`.

   They're sent with `app.emit("voice://listen", evt)` to all windows. The session id tells
   each window whose session it is.
6. **`VoiceListener` state.**
   - Holds `Mutex<Option<ActiveListen>>` and `next_session: AtomicU64`.
   - `ActiveListen` holds `session`, `stream: cpal::Stream`, `guard: MicGuard`,
     `hold: Arc<AtomicBool>`, `stop: Arc<AtomicBool>` and the worker `JoinHandle`.
7. **Commands.**
   - `voice_listen_start(app, device_name: Option<String>) -> Result<u64, String>`:
     1. Requires `WhisperServer` to be Ready, failing with `"Speech recognition is not
        ready"`.
     2. Takes the `MicLock` guard.
     3. Creates a bounded `std::sync::mpsc::sync_channel::<Vec<f32>>(64)`, opens the
        stream with `on_mono` doing `try_send(chunk.to_vec())` (chunks are dropped when
        full, with a rate-limited `warn!`), and with `on_error` setting a shared
        `device_failed` flag.
     4. Spawns the worker thread.
     5. Emits `Started` and returns the session id.

     A second start while one is active returns `Err("Already listening")`.
   - `voice_listen_stop(app)`: sets `stop`, drops the stream and guard, joins the worker
     and emits `Stopped { reason: User }`. If nothing is active it does nothing and returns
     `Ok(())`.
   - `voice_listen_hold(hold: bool)`: sets the `hold` flag, for webview `<audio>`/`<video>`
     playback in phase 04.
8. **Worker thread.** It loops on `recv_timeout(100 ms)`:
   - **Exit:** if `stop` is set, exit.
   - **Device failure:** if `device_failed` is set, emit `Stopped { reason: Device }`,
     clear the active slot through `app.state::<VoiceListener>()` and exit.
   - **Hold:**
     - `held = hold || TtsEngine::is_playing()`.
     - When it becomes true: `segmenter.reset()`, emit `Paused { paused: true }`, drop the
       audio.
     - When it becomes false: start a 400 ms tail during which audio is still dropped
       (room echo), then emit `Paused { paused: false }`.
     - Being held resets the idle clock.
   - **Normal flow:**
     1. Resample to 16 kHz, slice into 256-sample frames and score each with
        `earshot::Detector::predict_f32`.
     2. Feed the segmenter.
     3. When a phrase finishes: `seq += 1`, emit `PhraseQueued`, and send `(seq, samples)`
        to a `tokio::sync::mpsc::unbounded_channel` read by one async task, spawned once
        per session with `tauri::async_runtime::spawn`.
     4. That task encodes with `audio::encode_wav(_, 16000)`, then calls
        `app.state::<WhisperServer>().transcribe(wav)`. It emits `Phrase { seq, text }` on
        success or `Error { message }` on failure, then carries on. Because it's one
        task, results come out in order.
   - **Idle:** if no phrase has been queued for 300 s (`IDLE_STOP = Duration::from_secs(300)`),
     emit `Stopped { reason: Idle }`, clear the active slot and exit.
9. Make `encode_wav` `pub(crate)`.
10. Run `./scripts/export-ipc-types.sh` and add the mocks.

## Test plan
- Unit tests for `segmenter.rs`, feeding synthetic frames and scores:
  - 1 s of voice between silences gives exactly one phrase, whose length includes the
    pre-roll.
  - 200 ms of voice gives no phrase (under `MIN_SPEECH_FRAMES`).
  - 2 s of voice, 500 ms of silence, then 2 s of voice gives one phrase (the gap is under
    `END_FRAMES`).
  - 35 s of continuous voice gives a 30 s phrase, then a second one.
  - `reset()` in the middle of a phrase gives nothing.
- Unit tests for `resample.rs`:
  - 48 kHz → 16 kHz in three uneven chunks gives the same length and values, within 1e-4,
    as `resample_linear` on the whole buffer.
  - A 16 kHz input passes through unchanged.
- `MicLock` unit test: `try_take(Listening)` while a `PushToTalk` guard is alive fails with
  the push-to-talk message, and the reverse gives the listening message. Both succeed once
  the guard is dropped.
- In the dev app, from the devtools console:
  1. `await __TAURI__.core.invoke('voice_listen_start', {})` after one push-to-talk use
     (so whisper is Ready).
  2. Listen with `__TAURI__.event.listen('voice://listen', console.warn)` and speak two
     sentences with a pause. That gives two `PhraseQueued`/`Phrase` pairs in order.
  3. Pressing F2 at the same time toasts the mic-in-use error.
  4. Playing an answer with F3 emits `Paused` true, then false.
  5. `voice_listen_stop` turns the OS mic indicator off.
