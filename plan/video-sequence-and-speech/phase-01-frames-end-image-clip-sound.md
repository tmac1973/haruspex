# Phase 01 — Full-size frames, end_image and clip sound

**Depends on:** nothing · **Enables:** 03 (hold-frame stills), 04–09 (chaining,
transitions, keyframes from existing clips), 14 (stills for cut mode)

## Goal

Give the video tools the three generation primitives every later phase leans
on: extract one frame at full size as PNG (including the true last frame),
let `generate_video` end on an `end_image` when the instance supports it, and
confirm and report a generated clip's own sound so later phases can keep it.

## Steps

1. In `frames.rs`, implement `extract_still`:
   - `Secs(t)`: `ffmpeg -nostdin -hide_banner -v error -ss <t> -i <file> -frames:v 1 -c:v png -y <out>`.
   - `First`: same with `-ss 0`.
   - `Last`: `ffmpeg -nostdin -hide_banner -v error -sseof -1 -i <file> -update 1 -c:v png -y <out>`
     (each decoded frame overwrites `out`, so the true last frame remains).
     When the clip is under 1 s, drop `-sseof`.
   - Run through `video::prepare_child` (bundled-library env), 30 s timeout.
   - Read the PNG header for width/height; fail if the file is missing or empty.
2. Default `out` is `stills_dir(episode)/<stem>-<first|last|t123.45>.png`;
   a given `out` must end `.png` and be inside the episode folder.
3. Add `video_still_extract` and register it; run `./scripts/export-ipc-types.sh`.
4. Register `video_still` in `video-frames.ts`. Its result names the PNG path,
   its size, and shows the image in the chat (same `registerLocalImage` path
   `video_frames` uses for its sheet).
5. In `toolchest/models.ts`, read `end_image` from the video instance meta
   (`meta.video`, `meta.api`) into capabilities; unknown keys are ignored so
   older servers still parse. Do not read `audio` as sound output.
6. In `videogen/toolchest.ts`, include `end_image` in the multipart body when
   `request.endImage` is set. A request with only `endImage` still uses
   multipart.
7. After storing a finished clip, call `video_probe` on it (Rust) and set
   `hasAudio`.
8. In `video-gen.ts`, add `end_image` to the schema and `startFrom`'s sibling
   `endFrom`; when the instance lacks `end_image`, return a tool error naming
   the instance and that it can only start from a picture.
9. Update the two guide pages, keeping each under 6 KB.

## Test plan

- Rust: `extract_still` on a fixture clip (`src-tauri/src/video/fixtures/`):
  `Last` equals the frame from `-ss <duration - 1/fps>` within one frame;
  `First` and `Secs` give the fixture's size; a sub-second clip works; `out`
  outside the episode is refused.
- TS: `buildVideoBody`/multipart includes `end_image` only when set; the tool
  refuses `end_image` on an instance without the capability; capability
  parsing keeps working on a meta without the new keys.
- Hand:
  - Against toolchest LTX-2.3, make a clip with start and end pictures; the
    result says it has sound and the player plays it.
  - Where no LTX-2.3 instance runs: `end_image` on a Wan2.2 I2V instance
    (`lightning1116` on asmodean), whose result says it has no sound.
