# Phase 04 — Relief and jitter on cell layers

**Depends on:** nothing · **Enables:** phase 05 (new layers use the same
shading), phase 06 (transition sets draw materials with relief).

**PR:** 2 of 3 ("texture renderer": phases 04–05).

## Goal

Every layer paints one flat colour, so bricks and cracks look drawn on.
Add two optional fields:

- `relief` (0–1) shades a layer's edges under a fixed top-left light:
  raised cells get a lit top-left edge and a shaded bottom-right edge, and
  cracks are cut in.
- `jitter` (0–1) varies each cell's shade, so a wall of bricks isn't six
  identical colours.

Absent or zero, both draw exactly what they draw today.

## Steps

1. **Before touching the renderer:** add a test that renders each
   prototype fixture recipe at 32 px, seed 1, 4 variants, and compares a
   64-bit FNV-1a hash of each image's raw bytes with
   `fixtures/prototype-pixels.json`. Generate the JSON once from the
   current code (a `#[ignore]`d test writes it), and commit both. This is
   the "same pixels as before" guard.
2. In `recipe.rs`, add `#[serde(default)] #[ts(optional)] relief: Option<f32>`
   to `Bricks`, `Cracks` and `Blotches`, and `jitter: Option<f32>` to
   `Bricks`. Validate both with `range(…, 0.0, 1.0)` when present.
3. Create `shade.rs`. Cells are given as a `Vec<u32>` the size of the tile
   (`NONE = u32::MAX` for mortar or background):
   - `lighten(c, t)`: mix toward white by `t`. `darken(c, t)`: multiply by
     `1 - t`.
   - `relief_raised(img, cells, relief)`: for each pixel in a cell (not
     `NONE`), if the pixel up or left (wrapping modulo `n`) has a different
     cell id, `lighten` by `0.35 * relief`. If the pixel down or right has
     a different id, `darken` by `0.35 * relief`. Wrapping keeps it
     periodic.
   - `relief_cut(img, mask, relief)`: for a groove mask (cracks), each
     non-groove pixel whose up or left neighbour (wrapping) is a groove is
     the lit lip: `lighten` by `0.35 * relief`. Each groove pixel whose
     down or right neighbour is not a groove is the shaded wall: `darken`
     by `0.25 * relief`.
   - `jitter_cells(img, cells, jitter, rng)`: draw one factor per cell id,
     `1 + jitter * 0.15 * (2u - 1)`, and multiply each of that cell's pixels
     by it. It is the only helper that uses `rng`, and it is called only
     when `jitter > 0`, so recipes without jitter consume the same random
     numbers as today.
4. In `layers.rs`:
   - `Bricks`: while drawing, record each pixel's cell id
     (`row * cols + col`, `NONE` for mortar). After drawing, call
     `jitter_cells` if `jitter > 0`, then `relief_raised` if `relief > 0`.
     Do not change the order of existing `rng` calls.
   - `Cracks`: record the crack mask. If `relief > 0`, call `relief_cut`.
   - `Blotches`: record the blotch mask as cell id 0 (inside) or `NONE`. If
     `relief > 0`, call `relief_raised` (a raised patch: moss, a mound).
5. Run `./scripts/export-ipc-types.sh`.
6. In `recipeGuide()`, append to the bricks, cracks and blotches lines:
   `relief?: 0–1` (bricks and blotches look raised, cracks look cut in,
   lit from the top left) and, on bricks, `jitter?: 0–1` (each brick a
   little lighter or darker). Add one rule line: "Use relief on built or
   lumpy surfaces; leave it off flat ones like water or painted floors."
   Add `relief: 0.5` to the subway-tile example's bricks layer.

## Test plan

- The pixel-hash test passes unchanged after steps 2–6: old recipes draw
  the same pixels.
- `every_layer_tiles_at_every_size` gains bricks with `relief: 1,
  jitter: 1`, cracks with `relief: 1` and blotches with `relief: 1`, held
  to the same seam bars as their plain forms.
- New test `relief_lights_the_top_left_of_each_brick`: bricks on a flat
  base, `relief: 1`. The mean luminance of pixels whose upper neighbour is
  mortar is above the mean of brick interiors. Pixels whose lower neighbour
  is mortar are below it.
- New test `relief_cuts_cracks_in`: pixels just below a crack are lighter
  than the base.
- New test `jitter_changes_brick_shades_only_when_set`: with `jitter: 0`
  the image equals the image with jitter absent; with `jitter: 1` at least
  two bricks of the same listed colour differ.
- Validation tests: `relief: 1.1` and `jitter: -0.1` are refused, naming
  `layers[0].relief` and `layers[0].jitter`.
- `write_previews` (ignored) gains a row with the subway example as revised,
  for a person to look at.

## Commit

`feat(textures): relief and jitter for bricks, cracks and blotches`

## Rollback

Revert the commit and rerun `./scripts/export-ipc-types.sh`. Recipes saved
with `relief` or `jitter` in a spec would then be refused by
`deny_unknown_fields`, and their texture fails with a named error until the
field is removed. Revert phases 05 and 06 first if they have landed:
phase 05 uses `shade.rs`, and phase 06's tests draw materials with
relief.
