# Phase 01 — Remove specialists

**Depends on:** nothing · **Enables:** phase 02 onward work on a Code tab with
no `ask_specialist`, no specialist settings and no session specialist toggles.

## Goal

Take the specialists feature out of the app whole: the tool, the three kinds,
the HTML runner they share, the Settings card, the session toggles, the dev
route, the stored settings and the guide page. Nothing else uses this code, so
this phase stands alone and ships on its own. The 3D helper (`check_3d`) is
untouched and stays the way to make 3D assets in the Code tab.

## Steps

1. Delete `src/lib/specialists/`, the two `ask-specialist` files, the two
   Settings components and their test, and `src/routes/dev/glb-runner/`.
2. Run `npm run check` and follow every error to the files listed above,
   removing the specialist field, option or branch in each. Do not leave
   compatibility shims.
3. In `stores/settings.ts`, remove the field from `AppSettings` and the
   defaults; in the load path, do not copy `rest.specialists` across, so an
   old settings file loses the key on the next save.
4. In `ExtrasMenu.svelte`, remove the specialists group and its "Use
   defaults" handling for specialists; the menu keeps the helpers group as is.
5. In Rust, remove the field from `CodeSessionRow` and `CodeSessionMetaPatch`
   and from every query in `code_sessions.rs`. Renumber the `row.get(n)` calls
   after the removed column. Add the dead-column comment beside the migration
   step in `mod.rs`.
6. Run `./scripts/export-ipc-types.sh`.
7. Update the guide: delete `specialists.md`, edit `helpers.md` and
   `code.md`, and drop the page from `guide.ts`. Grep `docs/` and `src/` for
   `specialist` (case-insensitive) and fix what is left, except
   `plan/specialist-models/`.
8. In GitHub: close #906 with a comment that points at this plan; remove the
   specialist hand-test items from #745.

## Test plan

- Unit: `ExtrasMenu.test.ts` covers a menu with helpers only and the count.
- Unit: a settings load test feeds a stored blob with a `specialists` array and
  asserts the parsed settings have no `specialists` key.
- Rust: `db/tests.rs` round-trips a Code session row without the field, and a
  database made with the column still opens and reads sessions.
- Manual: in `GDK_BACKEND=x11 npm run tauri dev`, open an existing Code
  session that had a specialist on; the header shows **Extras** with helpers
  only, a turn runs, and Settings → Code has no Specialists card.

## Commit

`refactor(code): remove specialists (ask_specialist, kinds, settings and session toggles)`

## Rollback

Revert the commit. The `specialists` column was never dropped, so old builds
read their data again. Settings saved by this build have lost the
`specialists` key, so a reverted build starts with an empty specialist list.
Safe to leave partly applied only at commit granularity: a half-removed field
fails `npm run check`.
