# Phase 01 — Binary detection, Settings → Video and `video_probe`

**Depends on:** nothing · **Enables:** every later phase (the binary resolver,
the `video` tool category, the folder rules, and the Settings section they all
extend)

## Goal

Haruspex finds ffmpeg, ffprobe and melt on Linux, macOS and Windows, shows what
it found in a new Settings → Video section, and offers the model one tool,
`video_probe`, that lists an episode folder's clips with their technical
details. This sets up the `video` tool category (offered in Chat and Code only,
and only when the binaries are found), the series/episode folder rules, and the
guide page. It's useful on its own: the model can answer "what's in ep12?"
accurately.

## Steps

1. **Binary resolver (`binaries.rs`).** For each of `ffmpeg`, `ffprobe` and
   `melt`, try these in order and take the first executable file that answers
   `-version` (`melt -version`) within 3 s:
   1. The Settings override path, passed in from the frontend.
   2. PATH. Write a small cross-platform `which` that walks
      `std::env::split_paths`, adding `.exe` on Windows; don't reuse the private
      one in `proxy/browser/detect.rs`.
   3. Kdenlive install locations:
      - Linux: `/usr/bin` and `/usr/local/bin`. Flatpak's melt can't be run
        from outside its sandbox, so it is not searched. When nothing is
        found and `flatpak info org.kde.kdenlive` succeeds, the hint is
        "Flatpak Kdenlive's melt can't be used; install the distro package or
        set a path.".
      - macOS: `/Applications/kdenlive.app/Contents/MacOS/` and
        `~/Applications/kdenlive.app/Contents/MacOS/`.
      - Windows: `%ProgramFiles%\kdenlive\bin\` and
        `%LOCALAPPDATA%\Programs\kdenlive\bin\`.

   Return `VideoBinariesStatus { ffmpeg, ffprobe, melt: Option<FoundBinary {
   path, version, source: 'override' | 'path' | 'kdenlive' }>, hints: Vec<String> }`.
   Every spawn in `video/` hides the console window on Windows:
   `shell::platform::apply_no_window` for `std::process::Command`, and
   `creation_flags(CREATE_NO_WINDOW)` under `#[cfg(windows)]` for
   `tokio::process::Command`. Video tools are available only when all
   three binaries are found.
2. **Folder rules (`paths.rs`).** `resolve_episode(working_dir, episode)`
   accepts a relative path inside the working folder (`ep12`, `ep12/raw`) and
   reuses `fs_tools/path.rs`'s workdir resolution, so `..`, absolute paths and
   escaping symlinks are refused the same way. When `episode` is empty, the
   working folder itself is the episode, for users who pick an episode folder
   directly. `resolve_media(working_dir, path, settings)` also accepts exactly
   `videoIntroPath` and `videoOutroPath` from Settings, read-only.
   `resolve_in_working(working_dir, path)` resolves any other path inside the
   working folder. Every write in later phases goes through `resolve_episode`
   or `resolve_in_working`, never `resolve_media`.
3. **Probe (`probe.rs`).** Run
   `ffprobe -v error -print_format json -show_format -show_streams <file>` for
   each file in the episode folder and one level of subfolders (so `ep010/raw/`
   is found). Skip `.haruspex/`. Consider files with extensions `mp4 mkv mov
   webm avi m4v flv ts mts`, plus `wav mp3 flac m4a ogg` as audio-only. Map to
   `ClipInfo { path (relative to the working folder), duration_secs, size_bytes,
   video: Option<{codec, width, height, fps_num, fps_den, pix_fmt, rotation}>,
   audio: Vec<{codec, channels, sample_rate}>, created: Option<String> }`,
   sorted by the OBS filename timestamp when present, then by name. Probe in
   parallel, 4 at a time, with a 20 s timeout per file.
4. **Commands.** `video_binaries_status(overrides)` and
   `video_probe_folder(working_dir, episode, overrides)`. Run
   `./scripts/export-ipc-types.sh`.
5. **Settings → Video (`VideoSection.svelte`).**
   - One row per binary: a status dot, the found path and version, and an
     override path input with a file picker.
   - The output preset select.
   - Intro and outro file pickers.
   - When melt or ffmpeg is missing, a one-sentence hint: "Install Kdenlive, or
     set the paths below." The detail of where Haruspex looked goes in a
     `title` tooltip.

   Store plain strings only (the settings snapshot rule).
6. **Registry gating.** Add `'video'` to the category union. In `registry.ts`,
   compute `videoTools` next to `musicGeneration` and offer the category only
   when it's true, and add `video` to `subtaskExcludes`. In `generationRefusal`,
   return "Video tools need ffmpeg, ffprobe and melt. The user can check
   Settings → Video." when they're unavailable, and "Video tools need a working folder."
   when `workingDir` is null.
7. **`video_probe` tool (`video.ts`).**
   - Schema: `{ episode?: string }`.
   - Result: a compact table, one line per clip (`path · 12:03 · 2560×1440 @ 60 ·
     h264 · aac 2ch`), followed by notes when clips differ in resolution, frame
     rate or codec ("Mixed sources: renders will scale to the preset").
   - Also lists the configured intro and outro when set, and any files in
     the series folder whose name starts with `intro` or `outro`, as
     candidates.
   - `displayLabel`: "Looking at clips in ep12".
8. **Guide page `docs/guide/video.md`.** Frontmatter title "Video" and a
   description. Sections:
   - "Set up video editing" (install Kdenlive, Settings → Video).
   - "Pick a folder" (series folder with episode subfolders, or one episode
     folder).
   - "Ask about your clips".
   - "What it doesn't do" (no live Kdenlive control, no effects authoring).

   Keep it under 6 KB.

## Test plan

- Rust unit tests:
  - `which` with a temporary PATH holding a fake executable (and `.exe` on
    Windows).
  - Override beats PATH; PATH beats the Kdenlive location.
  - A non-executable override is reported, not used.
  - `resolve_episode` refuses `..`, absolute paths and escaping symlinks, and
    accepts `ep12/raw`.
  - `resolve_media` accepts the intro path from Settings but refuses any other
    outside path.
  - Probe JSON mapping from saved ffprobe output fixtures: OBS mkv, phone mov
    with rotation, audio-only wav.
- Vitest:
  - The registry offers `video_probe` in Chat with a folder and binaries, and
    not in Chat without a folder, in a subtask, in Jobs or in the Shell tab.
  - `generationRefusal` text for each case.
  - `VideoSection` renders found/missing states and saves the override path
    as a string.
- Manual, Linux: Settings → Video shows `/usr/bin/melt 7.42.0` and ffmpeg. In
  Chat with `/netstuff/spronglehump/videos` picked, "what's in ep010?" lists
  the OBS recording and the intro.
- Manual, mactest and wintest (`ssh haruspex-mac` / `ssh haruspex-win`): with
  Kdenlive installed and nothing on PATH, Settings → Video finds melt, ffmpeg
  and ffprobe inside the Kdenlive install; without Kdenlive it shows the hint.
