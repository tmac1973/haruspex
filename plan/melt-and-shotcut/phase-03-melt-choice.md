# Phase 03 — Choose the bundled melt in Settings → Video editing

**Depends on:** 02 · **Enables:** 04, 09; video editing without Kdenlive
installed

## Goal

`binaries.rs` finds the bundled melt the same way it finds the bundled
ffmpeg, and Settings → Video editing gets a melt choice: Auto, Bundled,
System or Custom. With Auto, which is the default, a fresh install renders
with no editor installed. This is the phase that delivers the first goal in
the overview.

## Files touched

- `src-tauri/src/video/binaries.rs` → rename `FfmpegChoice` to `ToolChoice`.
  `BinaryOverrides` gains `melt_choice: ToolChoice`, and `ffmpeg_choice`
  keeps its name and serde key. `Tool::Melt` resolves in the same order as
  ffmpeg: Override (only with Custom), Bundled, PATH, then the Kdenlive and
  Shotcut install locations (System skips Bundled, Bundled is only the
  bundled copy). The module docs and the `BinarySource::Kdenlive` doc become
  "an editor install". Add Shotcut's locations: macOS
  `/Applications/Shotcut.app/Contents/MacOS/melt`, Windows
  `%ProgramFiles%\Shotcut\melt.exe`, Linux PATH plus
  `/opt/shotcut/Shotcut.app/bin/melt` (the tarball install). Flatpak and
  Snap installs of either editor aren't searched: their melt can't run
  outside the sandbox, and the bundled melt covers those users. The variant
  `BinarySource::Kdenlive` is renamed `BinarySource::Editor`.
- `src-tauri/src/video/project.rs` → the `VideoSettings` doc comment.
- `src/lib/ipc/gen/*` → regenerated by `./scripts/export-ipc-types.sh`
  (`ToolChoice.ts` replaces `FfmpegChoice.ts`, `BinaryOverrides.ts`,
  `BinarySource.ts`).
- `src/lib/stores/settings.ts` → `videoMeltChoice: ToolChoice`. A stored
  value is read like `storedFfmpegChoice`: a valid value is kept, otherwise
  `'custom'` when `videoMeltPath` is set and `'auto'` when it isn't. Default
  `'auto'`. `FFMPEG_CHOICES` becomes `TOOL_CHOICES`.
- `src/lib/video/binaries.ts` → passes `meltChoice` in the overrides.
- `src/lib/components/settings/VideoEditingSection.svelte` → a melt select
  next to the ffmpeg one with the same four options. The melt path field
  shows only with Custom, as the ffmpeg fields do. The `LOOKED` tooltip text
  for melt names the editor installs instead of Kdenlive alone.
- `src/lib/components/settings/VideoEditingSection.test.ts` → cases for the
  melt choice.
- `src/lib/skills/needs.ts`, `src/lib/agent/tools/registry.ts` → the refusal
  text no longer suggests installing Kdenlive. It says "ffmpeg, ffprobe and
  melt weren't found: Settings → Video editing".
- `docs/guide/settings-tools.md`, `docs/guide/video-editing.md` → nothing to
  install: melt ships with Haruspex. Document the melt choice.
- `plan/video-editing/overview.md` → strike "Bundling ffmpeg or melt" from
  its non-goals, with a pointer to this plan.

## Steps

1. Rename the enum in Rust and add `melt_choice`. `resolve` for `Tool::Melt`
   reads `melt_choice` where ffmpeg reads `ffmpeg_choice`.
2. Unit tests in `binaries.rs`, using the temp-dir fakes the ffmpeg tests
   already use: Auto prefers bundled, System skips it, Bundled ignores PATH,
   Custom uses only the path.
3. Regenerate the IPC types, then update the settings store, its migration
   test, and the section.
4. Update the refusal strings and the guide pages, checking both pages stay
   under 6 KB, and run `node scripts/guide-check.mjs < /dev/null`.

## Build gate

- `cargo fmt -- --check`, `cargo clippy -- -D warnings`, `cargo test`.
- `./scripts/export-ipc-types.sh` with no diff afterwards.
- `npm run check`, `npm run lint`, `npm run test`, `npm run format:check`.
- `node scripts/guide-check.mjs < /dev/null`.

## Test plan

- On a machine with Kdenlive removed (`dnf remove kdenlive mlt`), the dev app
  shows melt as bundled, and "make a cut of these two clips and render it"
  works end to end in Chat.
- With Kdenlive installed and melt set to System, the section shows Kdenlive's
  `melt-7` and renders with it.
- A settings blob from before this phase, with `videoMeltPath` set, loads as
  Custom with the same path.

## Commit

`feat(video): pick the bundled melt by default`

## Rollback

Revert the commit and regenerate the IPC types. A stored `videoMeltChoice`
is then ignored as an unknown key, and melt resolves from PATH or Kdenlive
again. Safe to revert on its own; phase 02's bundle stays in place unused.
