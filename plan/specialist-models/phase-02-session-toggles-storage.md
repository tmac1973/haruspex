# Phase 02 — Per-session specialist toggles (storage)

**Depends on:** 01 · **Enables:** 03 (the tool asks which specialists a session has), 04 (the header menu writes the toggles).

## Goal
Give each Code session a stored list of the specialists it offers, with "the entries marked on by default" as the meaning of an unset list. Storage and store accessors only; no UI. Labelled `no-docs`.

## Files touched
- `src-tauri/src/db/mod.rs` — migration: `ALTER TABLE code_sessions ADD COLUMN specialists TEXT`, with a comment in the style of the neighbouring ones.
- `src-tauri/src/db/code_sessions.rs` — `CodeSessionRow.specialists: Option<String>` (JSON array of entry ids; `null` = the on-by-default entries); read it in every row query; `CodeSessionMetaPatch.specialists: Option<Option<String>>` so a patch can set or clear it; copy it in `code_session_fork`'s insert.
- `src-tauri/src/db/tests.rs` — tests for the column.
- `src/lib/ipc/gen/CodeSessionRow.ts`, `src/lib/ipc/gen/CodeSessionMetaPatch.ts` — regenerated by `./scripts/export-ipc-types.sh`.
- `src/lib/stores/code.svelte.ts` — a `specialists: string[] | null` field on the session object, loaded from the row, and `setSessionSpecialists(ids: string[] | null)` that saves through `code_session_update_meta`.
- `src/lib/specialists/session.ts` — new: `sessionSpecialists(stored: string[] | null): SpecialistEntry[]`.
- `src/lib/specialists/session.test.ts` — new.
- `src/lib/e2e/codeDb.ts` — carry the new field in the e2e fake so the e2e specs keep compiling.

## Steps
1. Add the migration line at the end of the `code_sessions` group in `db/mod.rs`.
2. Add the field to `CodeSessionRow` with a doc comment ("JSON array of specialist entry ids this session offers; `null` means the entries marked on by default"), select it in every query that builds a row, and write it in `update_code_session_meta` when the patch has it. Forks copy the source's value.
3. Run `./scripts/export-ipc-types.sh`.
4. In `code.svelte.ts` parse the JSON on load (a parse error or non-array becomes `null` and logs a `console.warn`), and add `setSessionSpecialists`, which stores `JSON.stringify(ids)` or `null` via `invoke('code_session_update_meta', { id, patch: { specialists } })`.
5. `sessionSpecialists(stored)`: when `stored` is `null`, return `specialistEntries().filter(e => e.onByDefault)`; otherwise return the entries whose ids are in `stored`, in Settings order. Ids of deleted entries are ignored.

## Build gate
`npm run check`, `npm run lint`, `npm run format:check`, `npm run test`; from `src-tauri/`: `cargo test`, `cargo clippy`, `cargo fmt -- --check`; the IPC drift check (`./scripts/export-ipc-types.sh` leaves no diff).

## Test plan
- Rust: a new session has `specialists = NULL`; `update_meta` sets and clears it; a fork copies it; a database from before the migration opens and reads `NULL`.
- `session.test.ts`: `null` gives the on-by-default entries; an explicit list gives exactly those, in Settings order; a deleted id is ignored; an empty array gives none.
- Existing `code.svelte.ts` and e2e specs pass unchanged.

## Commit
`feat(code): store which specialists a Code session offers`

## Rollback
Revert the commit. The added column stays in users' databases and is ignored by older builds (SQLite keeps unknown columns harmlessly), so no down-migration is needed.
