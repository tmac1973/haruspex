# Phase 24 — The bundled engine runs Ming-Image

> **Blocked (2026-09-30).** `measurements-phase-17.md` §4: sd.cpp
> `master-929` needs the 36.7 GB BF16 text encoder, lost the Vulkan device
> with the encoder on the GPU, sampled at ~120 s/step with it on the CPU
> (ComfyUI: 1.5 s), and failed in the VAE. First step before any code:
> re-test on a newer build, with the BF16 DiT, and on NVIDIA or Metal
> hardware. Until then Ming is ComfyUI-only.

**Depends on:** 17 (step 4), 18, 19 · **Enables:** 25.

## Goal

A user with no ComfyUI gets the same sheets, with the same alpha, from the
bundled `sd-server`, started on demand as it is now.

## Why

The overview's second success criterion: "A user with no ComfyUI can opt into
the local engine, and the same job produces the same shape of output."
stable-diffusion.cpp documents Ming-Image with RGBA output and int8 convrot
weights (`docs/ming_image.md`), but the pinned build (`master-890-74988b2`)
predates it, and whether the transparent start works through its HTTP routes
is phase 17 step 4's question.

## Files touched

- `scripts/fetch-sdcpp.sh` — `SDCPP_VERSION` bumped to the build phase 17
  measured.
- `src/lib/image/local/capabilities.json` — regenerated by
  `scripts/sdcpp-capabilities.sh`; `transparency` added to what it records.
- `src-tauri/src/image_engine.rs` — start arguments per family: `--llm`,
  `--vae`, `--tokenizer`, CPU offload of the text encoder.
- `src/lib/image/local/adapter.ts` — the transparent start as an img2img
  request (or the native route, per phase 17), and the shift if the route
  exposes one.
- `src/lib/image/local/backend.ts` — paths per file role from phase 19.
- `docs/image-generation.md` — the local section.

## Steps

1. **Bump and regenerate.** New version in `fetch-sdcpp.sh`; run
   `sdcpp-capabilities.sh`; review the fixture diff line by line. A capability
   that disappeared is a finding, not noise.
2. **Start arguments.** Ming needs `--diffusion-model`, `--llm`, `--vae` and
   `--tokenizer`, and on 16 GB the text encoder offloaded to CPU. The engine
   is started with the files phase 19 resolved; an incomplete download refuses
   to start and says which file is missing.
3. **Transparency.** Implement whichever route phase 17 found keeps alpha.
   `capabilities().transparency` is true only when that route exists in the
   pinned build's route table AND the loaded model's family is Ming — the same
   gating pattern the IP-Adapter capability used.
4. **Shift at 2048.** If the route cannot set the flow shift, 2048 sheets
   stay opaque (spike, finding 4). Then the local backend caps sheet size at
   1024 and phase 21's grouping splits accordingly — reported, not silent.
5. **Remove what IP-Adapter needed.** The `--ip-adapter` flag handling and the
   reference path in the adapter go, as they did for ComfyUI in phase 18.
6. **Packaged-build check** (carried from phase 15): the new binary and its
   `sd-libs` land in a packaged build, and nothing starts at boot.

## Test plan

- The capabilities fixture test: a build without the transparency route
  reports `transparency: false`, whatever model is loaded.
- Start arguments for a Ming entry include all four files; a missing
  tokenizer is a start refusal naming it.
- Adapter: `transparent: true` produces an img2img body with a transparent
  init image of the requested size and the measured strength; `false`
  produces a plain txt2img body.
- **Live, env-gated:** `asset-smoke` through the bundled engine writes its
  sprites with real alpha.
