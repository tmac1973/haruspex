# Phase 01 — Home tab, card store and live cards

**Depends on:** nothing · **Enables:** every later phase (the tab, the
`home_cards` table, the card frame and the Add card menu)

**External prerequisite:** the job editor rework in another session is merged
to `main` before this phase starts, because step 8 adds a small hook to
`JobsTab.svelte`.

## Goal
Ship a Home tab, first in the tab bar, with the two live cards that need no
schedule and no model: **Jobs** (the current run, the queue and recent runs
across all jobs) and **Code sessions** (sessions running, queued or needing
attention, each clickable). Cards are stored in a new `home_cards` SQLite table
and can be added, removed, reordered and set to normal or wide. A new user sees
both live cards by default. This is useful on its own and tests the layout
before any job work.

## Steps
1. Add the table in `db/mod.rs`:
   `home_cards(id TEXT PRIMARY KEY, card_type TEXT NOT NULL, job_id TEXT
   NULL REFERENCES jobs(id) ON DELETE SET NULL, position INTEGER NOT NULL,
   size TEXT NOT NULL DEFAULT 'normal', config TEXT NOT NULL DEFAULT '{}',
   notify INTEGER NOT NULL DEFAULT 0, last_result TEXT NULL, updated_at
   INTEGER NULL, created_at INTEGER NOT NULL)`. The connection already runs
   `PRAGMA foreign_keys=ON` (`db/mod.rs`), so deleting a job clears
   `job_id` with no extra code; a test holds it.
2. Write `db/home_cards.rs` with a `#[ts(export)]` `HomeCard` struct and the
   five queries. `update` takes the id and optional `size`, `config` and
   `notify`, and changes only the fields given. `reorder` takes the full ordered id list and rewrites
   `position` in one transaction.
3. Add `list_recent_runs(limit)` to `db/runs.rs` returning run id, job id,
   job name, job type, status, trigger, started/finished times, ordered by
   `COALESCE(finished_at, started_at, queued_at) DESC`.
4. Add and register the commands; run `./scripts/export-ipc-types.sh`.
5. Extend `activeTab.svelte.ts`; update `TabBar.svelte` and `+page.svelte`.
   The `+layout.svelte` digit handler already uses `mainTabs()`, so Ctrl+1
   becomes Home with no change there; check that `+layout.svelte:243` and the
   other `setActiveTab` callers still compile.
6. Build `cardTypes.ts` with the two live types (`jobs`, `code_sessions`).
   The registry is the one place later phases add types. `HomeTab` renders a
   row whose `card_type` is not in the registry as an "Unknown card" frame
   with Remove as its only menu item, so a rollback of any later phase
   leaves Home usable.
7. Build `homeCards.svelte.ts`: `loadHomeCards`, `addCard(type, config,
   jobId?)`, `removeCard(id)`, `moveCard(id, dir)`, `setCardSize(id, size)`.
   On first load with an empty table, create `jobs` then `code_sessions`.
   A removed live card can be added back from Add card; the seeding runs only
   once, recorded by a `homeSeeded` boolean in settings.
8. `JobsCard`: the current run from `getCurrentRun()` (name, current step,
   checklist progress "3/7" from the loop step's `checklist` for
   autonomous-coding, "waiting for model" when `waitingForSlot`), the queue
   depth from `getQueueDepth()`, and the five latest runs from
   `db_job_runs_list_recent` refreshed on each `job-run` engine event. A row
   click calls `selectJob(jobId, runId)` from `jobsTabSelection.svelte.ts`,
   then `setActiveTab('jobs')`. `jobsTabSelection` holds one pending
   `{ jobId, runId }`; an `$effect` in `JobsTab.svelte` applies it on mount
   and whenever it changes (sets `selectedId`, `selectedRunId`, and
   `runViewOpen` when a run id is given), then clears it.
9. `CodeSessionsCard`: rows from the engine's `sessions.list` (all windows),
   each with title, root and a status chip: Needs attention (a pending prompt
   for that session in `prompts.svelte.ts`), then the item's `status` from
   `sessions.list` (`CodeSessionStatus`): `running` → Running, `queued` →
   Queued, `waiting-shell` → Waiting on shell, `idle` → Idle. Idle sessions are hidden; the card shows "No active
   sessions." when none remain. Sort: needs attention, running, queued.
   Click does `setActiveTab('code'); await openSession(id)`.
10. Update `shortcuts.ts` so the digit entry reads "Switch to the Home, Chat,
    Jobs, Shell or Code tab (Chat and Jobs only in lean mode)"; update the
    `shortcuts` page to match exactly.
11. Write `docs/guide/home.md` (title, description, adding and arranging
    cards, the two live cards, not in lean mode) and note Home in
    `lean-mode.md`.

## Rollback
Revert the commit. The `home_cards` table stays in existing databases but
nothing reads it; leaving it is harmless. A stored `haruspex.activeTab` of
`'home'` falls back to `'chat'` because `load()` validates against the list.
