# Phase 07 — The embedding index in Rust

**Depends on:** 01, and phase 06 meeting its bar (phase 06 step 7 stops the
plan otherwise) · **Enables:** vector candidates in `search_code` (phase
08)

## Goal

A per-project index of chunk embeddings, kept in its own SQLite file in the
app's data folder, refreshed incrementally (only changed files are embedded
again), and searchable by cosine similarity. It uses phase 01's chunking, so
keyword and vector candidates line up. No UI and no tool change yet; it ships
tested and unused.

## Files touched

- `src-tauri/src/code_index/mod.rs` — new: the commands, the build lock and

- `src-tauri/src/code_index/store.rs` — new: the SQLite file.
- `src-tauri/src/code_index/embed.rs` — new: the `/v1/embeddings` client.

- `src/lib/ipc/gen/*` — regenerated by `./scripts/export-ipc-types.sh`.

## Steps

1. **Endpoint**: `#[derive(Deserialize, ts_rs::TS)] #[ts(export)] pub struct
   EmbedEndpoint { base_url: String, api_key: Option<String>, model: String }`.
   The caller resolves the key (phase 08 does it in TS with
   `getApiKeyValue`).
2. **File**: resolve the root with `code_tools::search::resolve_code_root`
   first (WSL roots included). The index is
   `<app data>/code_index/<first 16 hex of sha256(resolved root + "\n" +
   normalized base_url + "\n" + model)>.sqlite`, so a changed endpoint or
   model is a different file and vectors from two models never mix. Tables:
   - `meta(key TEXT PRIMARY KEY, value TEXT)`: `root`, `model`, `dims`,
     `built_at`, `used_at`;
   - `files(path TEXT PRIMARY KEY, mtime INTEGER, size INTEGER, hash TEXT)`;
   - `chunks(path TEXT, start_line INTEGER, end_line INTEGER, vector BLOB,
     PRIMARY KEY(path, start_line))`, the vector as little-endian `f32`s,
     normalized to length 1.
3. **Embedding client** (`embed.rs`): POST `<base>/v1/embeddings` with
   `{ model, input: [texts] }` and the bearer key, using
   `sidecar_util::http_client` (no proxy, as for other inference calls); parse
   `data[].embedding` in `index` order. Batches of 32 chunks, each cut to
   4 000 characters and prefixed with its path. Timeout 60 s a batch.
4. **Build** (`async fn build(index, root, endpoint)`): list files with
   `code_tools::rank::candidate_files` and chunk them with `chunk_file`. A file
   whose `mtime` and `size` match its row is unchanged. Otherwise hash it
   (SHA-256); if the hash matches, update the row's `mtime` only; if not,
   delete its chunks, embed its new chunks and write them. Delete rows and
   chunks for files that are gone. Commit per file, so an interrupted build
   keeps what it did. At the end set `built_at`.
5. **One build at a time per index**: a process-wide map of index file →
   `Arc<tokio::sync::Mutex<()>>`, plus a `building` flag per index.
6. **Refresh** `code_index_refresh(root, endpoint, wait: bool, wsl_distro?) ->
   IndexStatus`:
   - `wait: true` takes the lock (waiting for a running build), runs a build,
     and returns the status;
   - `wait: false` on an index with no running build spawns the build with
     `tauri::async_runtime::spawn` and returns at once with `building: true`
     and the previous build's `error`, if any, so a caller sees why the last
     try failed. The call reads `error` into the status first, then spawns
     the build, which clears the stored error as it starts;
   - `wait: false` while a build runs returns at once with `building: true`.
   Every call writes `used_at`.
7. `IndexStatus { ready: bool, building: bool, files: u32, chunks: u32,
   total_files: Option<u32>, error: Option<String> }`, `#[ts(export)]`.
   `ready` means `built_at` is set (one full build has finished). `files` is
   the rows written so far. `total_files` is the running or last build's walk
   count, `None` until a walk has finished listing files. `error` is the last
   build's error if it failed, cleared when a build starts.
8. **Query** `code_index_query(root, endpoint, query, limit, wsl_distro?) ->
   Vec<SearchChunk>` (phase 01's struct): embed the query, load all vectors,
   score by dot product, and return the top `limit` with their text read from
   disk now (lines `start..end` of the current file, through the resolved
   root) and `score` set to the cosine. A chunk whose file no longer has that
   many lines is skipped. Writes `used_at`.
9. **Journal and pruning**: open each index with `journal_mode=DELETE` (the
   default rollback journal, not WAL), so an index is one file at rest. At
   startup, in a background task, open each `.sqlite` file under
   `code_index/`, read `meta.used_at`, and delete the file (and any
   `-journal`, `-wal` or `-shm` file beside it) when `used_at` is over 30 days
   old or missing. A file that won't open is deleted too.
10. Run `./scripts/export-ipc-types.sh`.

## Test plan

Rust tests with a local fake `/v1/embeddings` server that returns a
deterministic vector per text (a hash spread over 8 dimensions):

- A first refresh embeds every chunk; a second one embeds nothing.
- Touching a file without changing it embeds nothing (hash match); editing it
  re-embeds only its chunks; deleting it drops its rows.
- A different model gives a different index file.
- A query returns the chunk whose fake vector matches best, with current
  text.
- `wait: false` on an unbuilt index returns `building: true` and the build
  finishes in the background; a second `wait: false` during it also returns
  `building: true`.
- An embedding error leaves earlier files' rows intact and reports `error`.
- Pruning deletes an index whose `used_at` is 31 days old and keeps one
  used today, even when the second file's mtime is old.

Manual: refresh the Haruspex checkout against compute2's
`Qwen-Qwen3-Embedding-0.6B.Q8_0` with `wait: true`; record the first build's
time and size in the commit message (expected about 3 minutes and tens of
MB), then edit one file and confirm the next refresh embeds only that file.
