# Phase 02 — Rerank client and a server's model list

**Depends on:** nothing · **Enables:** the reranker on the Search row (phase
05), the embedding endpoint's model picker (phase 08), and later reranking
elsewhere (memory recall, `load_tools`)

## Goal

A generic Rust command that sends a query and documents to any `/v1/rerank`
server and returns their order, and a second one that lists a server's models
with the capabilities it reports, so Settings can offer only rerank (or
embedding) models. Not tied to code search, so memory recall can use them
later. No UI yet.

The inference probe isn't reused for the model list: for llama-toolchest it
reads `/api/service/loaded-models`, which lists the models chat completions
will serve, and its `capabilities` there are context and vision, not a kind.
Toolchest's `GET /v1/models` lists every model, rerank and embedding ones
included, with `meta.capabilities` such as `["rerank"]` or
`["embedding", "tools"]` (checked against compute2 on 2026-11-02).

## Steps

1. `rerank_documents(base_url, api_key?, model, query, documents, timeout_ms?)
   -> RerankResult` where `RerankResult { order: Vec<RerankScore> }` and
   `RerankScore { index: u32, score: f32 }`, both `#[ts(export)]`, sorted by
   score, highest first.
2. Normalize `base_url` with `inference::normalize_base_url` and POST to
   `<base>/v1/rerank` with `{ model, query, documents }` and
   `Authorization: Bearer <key>` when a key is given. Use
   `sidecar_util::http_client` with the timeout (default 15 000 ms, clamped to
   1 000–60 000). That client has no proxy, the same as
   `probe_inference_server`: inference servers are reached directly.
3. Accept both response shapes in use: `{ results: [{ index,
   relevance_score }] }` (llama.cpp, toolchest, Cohere/Jina-style) and
   `{ data: [{ index, score }] }`. Anything else is an error naming the
   server's HTTP status and the first 200 characters of the body.
4. Cut each document to 4 000 characters before sending, so one long chunk
   can't overflow a reranker's context.
5. `list_server_models(base_url, api_key?) -> Vec<ServerModel>` with
   `ServerModel { id: String, capabilities: Option<Vec<String>> }`,
   `#[ts(export)]`: GET `<base>/v1/models` (same client, 10 s timeout) and
   read `data[].id` and, when present, `data[].meta.capabilities` as an array
   of strings. Servers that don't report it (llama-server, LM Studio) give
   `None`. Sorted by id.
6. `src/lib/rerank.ts`: `export interface RerankEndpoint { url: string; keyId:
   string | null; model: string }`; `rerankDocuments(endpoint, query,
   documents, timeoutMs?)` and `listServerModels(url, keyId)`, each resolving
   the key with `getApiKeyValue` after `apiKeysReady()`, as
   `probeInferenceServer` does, and calling `invoke` with the literal command
   name.
7. Run `./scripts/export-ipc-types.sh`.

  `meta.capabilities` and on a plain OpenAI list without `meta`.

  `rerankDocuments` on it with the spike's three-document example puts the
