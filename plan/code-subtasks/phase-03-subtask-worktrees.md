# Phase 03 — Rust: subtask worktrees, diff and apply

**Depends on:** nothing (independent of 01–02; numbered here because phase 04
needs both) · **Enables:** phase 04 (writing children)

## Goal

Rust commands to give a writing child its own worktree based on a snapshot of
the session's folder as it is now (uncommitted and untracked files included),
with the folder's ignored dependency folders linked in. Further commands
compute the child's changes as a patch and apply that patch back to the folder.
If the patch doesn't apply directly, a three-way merge is tried in a scratch
tree, and a conflict leaves the folder untouched. Nothing here touches the
user's index, stash, branches or HEAD. This phase has no UI and no model-facing
change.

## Steps

1. **Snapshot.** `snapshot_commit(place, root) -> Result<String, String>`:
   with `GIT_INDEX_FILE` set to a temp file under the repo's git dir,
   `git read-tree HEAD`, `git add -A -- :/ <excludes>`, `git write-tree`, then
   `git commit-tree <tree> -p HEAD -m "haruspex subtask base"`. Return the
   commit id. The user's index is never read or written. The commit stays
   unreferenced, so `git gc` collects it once the worktree is gone. A repo
   with no commits yet makes the commit with no `-p`.
2. **Dependency links.** Every git command in this module runs at the
   repository top (`locate`'s `top`) of the checkout it acts on, and every
   path below is relative to that top, even when the session's folder is a
   subfolder. Fixed candidates: `node_modules`, `.venv`, `venv`, `vendor`. A
   candidate is linked when it exists as a directory at the source checkout's
   repository top and `git check-ignore -q <name>` says it is ignored; it is
   linked at the same path at the worktree's top.
   Linking is a symlink on Linux/macOS and inside WSL, and a directory
   junction (`mklink /J`) on Windows hosts. The `<excludes>` in every
   `add -A` in this module is `:(top,exclude)<name>` for each linked name, so a
   link is never recorded as a change.
3. **Create.**
   `#[tauri::command] code_subtask_worktree_create(folder, session_id,
   wsl_distro) -> SubtaskWorktree { path, root, base, linked: Vec<String> }`:
   take a snapshot, then
   `git worktree add --detach <repo>-worktrees/.subtasks/<session_id>-<n> <base>`
   (no branch is created), link the dependencies, and return the same
   subfolder as `root`, as `add_fork_worktree_in` does. `<n>` counts up from 1
   past any existing folder. Errors when the folder isn't in a git repository
   ("<folder> is not in a git repository.") or git isn't installed.
4. **Diff.** `#[tauri::command] code_subtask_worktree_diff(path, base,
   wsl_distro) -> SubtaskPatch { patch: String, files: Vec<String> }`: a temp
   index in the worktree, `read-tree <base>`, `add -A -- :/ <excludes>`,
   `write-tree`, then `git diff --binary <base> <tree>`. `files` is
   `--name-only` of the same diff. An empty patch means no changes.
5. **Apply.** `#[tauri::command] code_subtask_apply(folder, patch, wsl_distro)
   -> SubtaskApply`. `SubtaskApply` is `Applied { files } | Conflict { files,
   message }`:
   1. `git apply --check --binary` from stdin at `folder`'s repository top; on success
      `git apply --binary` (working tree only, no `--index`) and return
      `Applied`.
   2. Otherwise: take a snapshot of the folder now (step 1), and make a scratch
      detached worktree at that snapshot under `.subtasks/apply-<n>`. Run
      `git apply --3way --binary` there.
   3. If the 3-way succeeds with no conflict markers (`git diff --check` is
      clean and `git ls-files -u` is empty), diff the scratch tree against its
      snapshot, run `git apply --check --binary` of that patch at `folder`'s repository top, and
      on success `git apply --binary`; return `Applied`. If that check fails
      (the folder changed again meanwhile), return `Conflict`.
   4. Otherwise return `Conflict` with the conflicted files and git's message.
      Either way the scratch worktree is removed with `--force` before
      returning. The folder is only ever written by a `git apply` that passed
      `--check`.
6. **Discard.** `#[tauri::command] code_subtask_worktree_discard(path,
   wsl_distro)`: remove the dependency links first (never follow them), then
   `git worktree remove --force`, then remove an empty `.subtasks` folder.
   Also add `code_subtask_worktrees_discard_session(folder, session_id,
   wsl_distro)`, which discards every `.subtasks/<session_id>-*` worktree of
   that folder's repo, for session delete.
7. Write `subtaskGit.ts` wrappers (`createSubtaskWorktree`,
   `subtaskWorktreeDiff`, `applySubtaskPatch`, `discardSubtaskWorktree`,
   `discardSessionSubtaskWorktrees`) with literal `invoke('…')` names.
8. Run `./scripts/export-ipc-types.sh` for `SubtaskWorktree`, `SubtaskPatch`,
   `SubtaskApply`.

## Test plan

Rust tests in `subtask_git.rs` against temp repos (host place):

- A snapshot includes a modified tracked file and an untracked file, and leaves
  `git status --porcelain`, `git stash list` and the index's `ls-files -s`
  output unchanged.
- A worktree created from a dirty folder contains the uncommitted edit, and
  `git branch` lists no new branch.
- An ignored `node_modules` is linked and an unignored `vendor` is not; an
  edit inside the linked `node_modules` doesn't appear in the diff.
- Diff of an unchanged worktree is empty; an edit, an added file, a deleted
  file and a binary file all round-trip through diff → apply.
- Apply with no concurrent change gives `Applied`.
- Apply after the folder changed a different region of the same file gives
  `Applied` through the 3-way path.
- Apply after the folder changed the same lines gives `Conflict`, and the
  folder's files are byte-identical to before.
- Discard removes the worktree and leaves the real `node_modules` intact.
- `discard_session` removes only that session's worktrees.
- A folder outside a repo errors with the sentence above.

TS: `subtaskGit.test.ts` checks each wrapper's command name and arguments.
