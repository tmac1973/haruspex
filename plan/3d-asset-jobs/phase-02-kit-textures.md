# Phase 02 — Build modules can use project PNGs as textures

**Depends on:** 01 · **Enables:** 06 (the texture tool in the job), 08 (Allow textures)

## Goal
The kit has no image API and the sandbox page (opaque `haruspex-artifact:`
origin) cannot fetch project files. Add `kit.texture(path)`: the tool finds
every `kit.texture('<literal>')` call in the module sources, reads those PNGs
from the project before the page starts, and the page turns each into a
`THREE.CanvasTexture` that `GLTFExporter` embeds in the GLB.

## Files touched
- `src/lib/helpers/three/textures.ts` (new) — `textureRefs(source): string[]` finds literal paths; `MAX_TEXTURES = 8`, `MAX_TEXTURE_BYTES = 4 MB`.
- `src/lib/helpers/three/textures.test.ts` (new).
- `src/lib/helpers/three/runModule.ts` — `ModuleRunOptions.textures?: Record<string, string>` (path → data URL); page decodes them before importing the module.
- `src/lib/helpers/three/kitEntry.ts` — `texture(path)` reads from a table the runner fills.
- `src/lib/agent/tools/check-3d.ts` — collects refs from build and anim sources, reads PNGs relative to the build module's folder, passes them in.
- `static/helpers/three-kit.js` — regenerated by `scripts/build-three-kit.mjs` from `kitEntry.ts`; the script itself needs no edit.
- `docs/guide/helpers.md` — one sentence on `kit.texture`.

## Steps
1. `textureRefs`: regex `/kit\.texture\(\s*(['"])([^'"\n]+)\1\s*\)/g`; return unique paths in order. A call whose argument is not a string literal is not found; the kit then throws at run time (step 3) with a clear message.
2. In `check-3d.ts` `source()`: for each ref, resolve against the build module's directory (`dirname(resolveShellPath(a.path, cwd))`), refuse `..` escaping the working dir, refuse non-`.png`, read through `assetIo(ctx).read`, refuse over `MAX_TEXTURE_BYTES`, more than `MAX_TEXTURES` refs is an error. Encode as `data:image/png;base64,…` and key by the literal string as written.
3. `kitEntry.ts`: `const textures = new Map<string, THREE.Texture>()`; export `kit.texture = (p) => { const t = textures.get(p); if (!t) throw new Error(\`kit.texture("\${p}"): no such PNG next to the module (paths are read before build runs, so pass a string literal).\`); return t; }`. Expose `HaruspexThreeKit.setTextures(map)`.
4. `runModule.ts`: embed `window.__hxTextures = {path: dataUrl}` (JSON). RUNNER, before creating the module script: for each entry `await createImageBitmap(await (await fetch(dataUrl)).blob())` (data: URLs fetch fine in an opaque origin), draw into a `document.createElement('canvas')`, make `new THREE.CanvasTexture(canvas)` with `colorSpace = SRGBColorSpace`, `wrapS = wrapT = RepeatWrapping`, `flipY = false`, and call `setTextures`. Any decode failure is `err('Texture <path> could not be decoded.')` and ends.
5. `GLTFExporter` embeds a CanvasTexture by drawing its canvas to PNG; the report's material line already prints `map WxH`. Phase 13's textured crate proves it end to end.
6. Schema/description: one sentence in `check_3d`'s description: "`kit.texture('textures/bark.png')` gives a Texture from a PNG next to the module; pass the path as a string literal."
7. Guide `helpers.md`: same sentence in plain words.
