# Phase 01 — IMAP: find requests, check Sent, move

**Depends on:** nothing · **Enables:** 02 (the reply header constant), 03
(the store keeps what the scan returns), 04 (the pipeline calls all four
commands)

## Goal

Give the frontend the IMAP operations the job needs, all in Rust: scan INBOX
for request candidates with the headers that decide trust, ask whether a
matching copy of a request is in the Sent folder, ask whether a reply Haruspex
sent has arrived, and move a message into one of the job's two folders
(creating it if needed). Authentication-Results is parsed into a small
struct for display. Nothing user-visible changes; the PR is labelled `no-docs`.

## Steps

1. Add `select_mailbox(session, name)`; make `select_inbox` call it with
   `"INBOX"`. Handles stay `uid_validity:uid` and always mean INBOX; Sent is
   only searched, never handed out as a handle.
2. `requests.rs` defines `pub const REPLY_HEADER: &str = "X-Haruspex-Reply";`.
   Phase 02 sets it from this constant; nothing else spells the name.
3. `scan_requests(account, phrase, since_ms: i64)`: `since_ms` is a Unix time
   in milliseconds. Select INBOX; UID SEARCH `SINCE <date> SUBJECT <phrase>
   FROM <account.email_address>`, where `<date>` is the UTC day of `since_ms`
   minus one day (SEARCH SINCE is whole days, and servers apply their own
   zone). The phrase and address go as IMAP literals, never spliced unquoted.
   Fetch `INTERNALDATE` and `BODY.PEEK[HEADER]` for each hit (PEEK, so nothing
   is marked read). In Rust, drop any hit whose INTERNALDATE is before
   `since_ms`, whose parsed From address is not exactly
   `account.email_address` (case-insensitive), whose subject doesn't contain
   the phrase case-insensitively (servers differ on SUBJECT matching), or that
   carries `REPLY_HEADER`. Of what is left, keep the newest 50 by UID and
   return them oldest first.
4. A reply that reached the Inbox without `REPLY_HEADER` (a server stripped
   it) is still caught by Phase 04's record of reply ids; `RequestCandidate`
   therefore drops the `is_haruspex_reply` field.
5. `auth_results::parse`: split each `Authentication-Results` value on `;`,
   read `dkim=`, `spf=`, `dmarc=` method results. Only headers whose authserv-id
   is the first (topmost) one count, since lower ones may be forged by the
   sender. `dkim` is `Pass` only when a passing signature's `header.d` (or
   `header.i` domain) matches the From domain. No header at all is `Absent`.
6. `sent_copy_matches(account, message_id, phrase) -> bool`, behind
   `email_request_sent_has`. IMAP `SEARCH HEADER` matches substrings, so the
   search only narrows; Rust decides:
   - Refuse (return `false`) unless the request's Message-ID passes
     `requests::is_valid_message_id`: one `<local@domain>`, no whitespace, CR,
     LF, `<` or `>` inside, at least 8 characters before the `@`, at most 250
     in all. Phase 02 uses the same function, so an id accepted here can always
     be replied to. A request with no Message-ID, an empty one or several is
     refused before any search.
   - Find the Sent mailbox through `sent_mailbox()`; none found is an error
     ("No Sent folder on this account."), not `false`. Refuse a mailbox that
     is `INBOX` or carries the `\All`, `\Junk` or `\Inbox` special-use flag,
     since mail from outside lands there too.
   - EXAMINE it (read-only), UID SEARCH `HEADER Message-ID <id>`, and fetch
     the headers of every hit.
   - `true` only when a hit's Message-ID equals the request's exactly, its
     From is `account.email_address`, its To includes `account.email_address`,
     and its subject contains the phrase (case-insensitive). So a forger who
     reuses the Message-ID of some other mail the user sent still fails: that
     mail went to someone else, without the phrase.
7. `move_to_folder`: LIST the folder; if it's missing, CREATE it (with a
   parent, for `Haruspex/Ignored`, created first). UID MOVE when the server
   advertises MOVE, otherwise UID COPY, `+FLAGS.SILENT (\Deleted)`, UID
   EXPUNGE (or EXPUNGE when UIDPLUS is missing, matching `trash_message`).
   The folder name is one of two constants, `Haruspex` and `Haruspex/Ignored`;
   the command refuses any other.
8. `reply_seen(account, reply_message_id) -> bool`, behind
   `email_request_reply_seen`: whether a message with exactly that Message-ID
   and From `account.email_address` is in INBOX, Sent, `Haruspex` or
   `Haruspex/Ignored` (each searched with `HEADER Message-ID`, then compared
   exactly, as in step 6). Phase 04 uses it to learn whether a reply was sent
   before a crash. A missing folder counts as no match.
9. Commands take `EmailAccount` like the existing ones and use the session pool
   (`checkout`/`checkin`) and `email_cancel` call ids the same way. The scan
   and Sent commands take the phrase; Rust never takes a folder name or
   recipient from the frontend beyond the two constants.
10. Run `./scripts/export-ipc-types.sh`.

## Test plan

- Unit: `auth_results::parse` on samples for Gmail self-mail, Fastmail, a
  forged lower header, a DKIM pass for another domain (→ not `Pass`), no header.
- Unit: the From and subject filter in `scan_requests` (extracted as a pure
  function) accepts `Ask Haruspex: x` for phrase `ask haruspex` and refuses
  `"Me" <me@other.com>` and display-name tricks like `"me@acct.com"
  <evil@x.com>`.
- Unit: the IMAP SEARCH command builder quotes a phrase with quotes and
  backslashes as a literal.
- Unit (the match logic extracted as a pure function over fetched headers):
  a Sent hit whose Message-ID only contains the request's (`.com`,
  `@mail.gmail.com`) fails; an exact id on mail to someone else fails; an
  exact id without the phrase fails; an empty, missing, short or doubled
  request id is refused before searching; a Sent mailbox flagged `\All` is
  refused.
- Manual, against the user's Gmail: send a self-email with the phrase from the
  phone; call `email_request_scan` from the devtools console and confirm one
  candidate with `auth` filled in; `email_request_sent_has` is true; a test
  email sent from another account with a forged From doesn't appear, or has no
  Sent copy. Record what Authentication-Results Gmail adds to self-mail in the
  PR body.
- Manual: `email_request_move` creates `Haruspex` and moves the message (in
  Gmail it becomes a label and leaves Inbox).
